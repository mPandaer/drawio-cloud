# Design

## Context

动机见 proposal.md。产品目录目前只有 `.gitkeep`，没有技术栈、业务实现、构建或测试命令，既有主规格为空。仓库约定业务实现放在产品仓库，编辑器以 submodule 固定 `v32.0.2`（`2201e54`）。

只读检查确认：`vendor/drawio/src/main/webapp/js/diagramly/EditorUi.js` 的 `installMessageHandler`、`initializeEmbedMode` 提供 JSON embed 协议，`load` 支持 `autosave`，模型变化发送完整 XML 的 `autosave` 事件，宿主可通过 `status` 回传状态。不能假设存在宿主发送 `action: save` 的接口。`Init.js`、`Editor.js` 提供启动配置；embed 默认不加载多数云盘客户端。`offline/lockdown` 会广泛关闭联网功能，不能将其作为产品常驻配置。当前编辑器可服务本地 webapp 产物，必要源码定制必须通过官方 Ant 构建重新生成产物。

## Goals / Non-Goals

**Goals:**
- 在一次性部署的单服务端进程中，建立可测试的身份、文档存储、租约与编辑器消息边界。
- 将服务端文档提交与浏览器“已保存”绑定，保证跨文件系统和数据库的故障一致性。
- 通过宿主集成和启动配置优先完成产品能力，保持编辑器升级成本可控。

**Non-Goals:**
- 不支持多副本服务端、跨主机分布式锁、增量文档保存或自动合并。
- 不自行实现官方在线素材提供方、云盘 OAuth 或服务器图片/PDF 渲染服务；保留编辑器现成可用功能，客户端导出可用，依赖额外服务的功能按官方实际条件工作。
- 临时提交文件与孤立正文清理不构成历史版本或备份。

## Decisions

### 1. 产品技术栈与模块职责

采用 TypeScript、pnpm workspace；`apps/web` 使用 React + Vite，`apps/server` 使用 Fastify 与 SQLite 驱动（优先 better-sqlite3），`packages/editor-bridge` 为与 React 无关的协议/保存状态模块，`packages/api-contract` 定义共享请求响应及错误类型。依赖实际安装时选择兼容的当前稳定版本并固定 lockfile，不在提案中猜测版本。服务端同步数据库操作保持短事务，文件 I/O 在事务前完成。

这些是可审阅的首期工程选择，不是既有项目事实。相比单独 Go 后端，统一语言减少小项目的类型转换和工具维护；相比重型框架与 ORM，Fastify 和显式迁移适合目前规模。验证使用 Vitest 做协议和服务端测试、真实 SQLite 和临时目录做集成测试、浏览器端到端测试做关键流程验收。

### 2. 身份与权限

数据库包含 users（用户名、密码哈希、角色、停用状态）、sessions（令牌哈希、用户、创建/过期时间）和永久 initialization 标记。用户名去除首尾空白并采用一致规范化唯一键；密码使用 Argon2id 哈希，不保存明文。初始化在数据库事务中检查并设置标记，永久关闭管理员注册。管理员创建的账号固定为普通角色，文件 owner 不因管理员编辑发生变化。

登录返回不可预测的随机会话令牌，Cookie 为 HttpOnly、SameSite=Lax，HTTP 下不设置 Secure，HTTPS 下设置 Secure；固定 7 天到期。变更类 API 同时验证 Origin 与会话绑定 CSRF 凭据，初始化注册也验证同源。密码修改/重置撤销全部旧会话；退出撤销当前会话。登录和初始化接口做轻量限速。所有文件端点以服务端身份检查权限，正文目录不能通过静态服务公开。

停用用户与会话撤销、租约删除在同一事务提交，保存提交阶段重复检查身份，避免请求开始时授权通过、停用后仍落库。停用可通过管理员修改账号状态恢复使用，不增加删除或角色变更。

### 3. 文件元数据与名称规则

files 包含随机 ID、owner_id、显示名、名称唯一键、当前 blob_key、revision、size、created_at、updated_at。文件名去除首尾空白，拒绝空值和路径分隔符，在用户范围按不区分大小写规则唯一；名称不会用于正文路径。搜索也使用同一大小写规则，默认按更新时间倒序，管理员列表显示归属并可搜索全部文件。

API 分为 bootstrap、auth、admin/users、files、files/:id/content 和 files/:id/edit-session。创建、导入、下载、重命名、删除均授权；列表不返回正文。错误结构提供稳定 code，区分未认证、无权限、重名、格式错误、超限、文件占用、锁失效、版本冲突和存储故障，前端映射中文提示。

导入只接受 `.drawio`，解析完整 XML，禁用外部实体，兼容 `<mxfile>` 内压缩或未压缩页面以及官方原生单页形式；限制解析/解压资源，避免小压缩文件耗尽内存。正文以完整文档为单位保存，不能将多页压缩文档误当无效；有效文档不强制格式转换。20 MiB 限制计量实际文档 UTF-8 字节，HTTP body 限制留出 JSON 编码开销并在正文层再次检查。

### 4. 文件系统与 SQLite 的提交一致性

不采用简单的“覆盖 file-id.drawio 然后更新数据库”：文件替换与 SQLite 提交不能成为一个原子事务，中途崩溃可能导致新正文配旧版本。

采用每次提交生成随机唯一 blob_key 的不可变正文，再由数据库指向当前正文：
1. 在持久化目录写入独立临时文件，完成写入与文件同步，在同一文件系统原子重命名为新 blob，同步目录。
2. 在短 SQLite 写事务内再次检查账号、权限、有效租约与 revision，以条件更新替换 blob_key、字节数并递增版本，提交后才返回成功。创建也只在 blob 就绪后提交元数据。
3. 提交失败留下的 blob 是孤立文件，不可通过 API 访问；成功替换后旧 blob 由清理程序删除。数据库使用 WAL 与 full 同步，数据目录要求支持相应原子操作的本地文件系统。
4. 启动时在服务接受写入前检查数据库引用、清理未引用正文与临时文件；运行时清理和正文读取通过同一存储协调器串行协调，避免删除正在提交或读取的 blob。发现数据库引用缺失时明确报存储错误，不伪造空白文档。

数据库原子提交是保存线性化点：崩溃发生前未提交时仍指向旧内容，已提交时新内容已落盘。客户端丢失响应时可发现版本冲突，不能默默覆盖。正文目录仅保留当前引用与短暂待清理文件，不向用户提供历史读取。删除先在事务检查锁并删除元数据，再清理正文；清理失败不会令已删除文件重新可见。

SQLite 比外部数据库更易单机部署；文件系统比 MinIO 减少服务和运维，自动保存全量重写在本项目规模下足够。MinIO 不会自动解决元数据一致性问题。

### 5. 服务端租约与并发保存

edit_leases 按 file_id 唯一，保存用户、会话、窗口随机 ID、随机 lease token 的哈希、expires_at。每次新申请生成新 token，只有原 token 且尚未过期才能续租；过期 token 不能复活。凭据绑定具体登录会话与窗口，浏览器不能跨标签页共享同一租约凭据。申请在短写事务内检查权限及有效锁；编辑器拿锁后读取正文与版本，再加载画布。

窗口每 10 秒续租，租约有效 60 秒。断网或续租结果不确定时，在本地到期前尝试续租，到期即暂停保存；恢复后先向服务端确认原租约仍有效，不自动重新申请并覆盖新窗口。管理员也不能抢占。退出显式释放，页面关闭的释放只能尽力发送，超时负责兜底。

保存必须携带 lease token 与 expectedRevision，并在 SQLite 提交事务检查当前租约和版本；并发请求最多一个成功更新当前版本。文件删除与锁申请用同样事务序列，避免检查后又被占用。服务端重启保留数据库租约，到期或明确释放后才允许新编辑，避免重启后旧窗口与新窗口同时获得有效锁。

### 6. 编辑器桥接与保存状态

启动 iframe 使用 `embed=1&proto=json` 和中文语言配置，在 init 后发送完整原生 XML 与 autosave 开关。宿主仅接收 iframe.contentWindow、预期 origin 和有效结构的消息；发送时指定 targetOrigin。每个打开周期具有独立会话世代，迟到消息与响应不能更新已切换文件状态。

桥接维护 latestContent、dirty generation、服务端 revision、租约和单个进行中的请求。变化重置 2 秒计时器，同时保留从首次待保存变化算起的 10 秒上限；只有内容改变才排队。保存期间合并待保存内容为最新完整快照，成功响应仅确认提交时对应 generation，后续修改继续 dirty 并使用返回 revision。手动保存/退出按实际官方 save、exit 事件及桥接 flush 处理，不发送不存在的 save action。

通过宿主状态栏和官方 status 消息显示服务端状态，必要时配置关闭与服务器语义不符的按钮/本地提示，确保编辑器不会提前宣称成功。普通网络/服务错误在租约有效时受控重试；权限错误、锁丢失、版本冲突暂停自动保存。冲突另存以当前用户为 owner 创建新文件，取得新锁后切换会话；重新加载前提示将放弃本地修改。

保留当前快照以提供本地下载；产品内离开先 flush，失败则提示下载或明确放弃，关闭页使用 beforeunload 的浏览器标准提醒。HTTP 局域网不依赖安全上下文限定的下载能力。不实现跨关闭草稿，并核实 embed 不主动启动官方本地文档草稿恢复。

### 7. 编辑器功能与部署

Compose 包含反向代理/静态服务与单个 API 服务端，将 `/` 指向产品、`/api` 指向后端、`/editor` 指向固定 submodule 的 webapp 产物。自部署启动配置修正编辑器基础地址及本地资源前缀，不硬编码 localhost，不将离线/lockdown 作为常驻选项；核心脚本、图形与语言包本地服务。

优先保留无需新增服务即可使用的官方在线素材、外部图片和客户端导出，不启用云盘 OAuth。官方素材接口、外部代理或远程导出有具体部署前提时，验证并说明限制，不把“保留官方功能”解释为自建所有外部服务。公网不可达时可选请求失败不能卡住 init。代理支持 iframe 同源嵌入，设置 frame-ancestors 为自身；外部素材需要的请求来源不能被一刀切 CSP 禁止。

产品构建复制固定 submodule 资源；如果需要修改源码，则在 fork 最小定制、采用 `vendor/drawio/etc/build/build.xml` 官方 Ant 构建，并记录产品 gitlink。部署挂载 `/data` 保存 SQLite 与 blobs，配置正文上限、端口和 HTTPS Cookie 行为，重建不清空挂载。运行时 API 单进程且不允许水平扩容。

## Risks / Trade-offs

- [没有版本、回收站和备份] → 明示永久删除与磁盘故障的恢复边界，不提供恢复承诺。
- [局域网 HTTP 无加密] → 配置兼容 HTTPS，按已确认范围提供 HTTP，不依赖 Secure Cookie 才能运行。
- [浏览器休眠与时钟/调度延迟造成锁过期] → 服务端时间权威判定，暂停保存并提供下载，禁用强制抢占。
- [正文与元数据跨介质] → 不可变正文先落盘、数据库指针后提交，加入写入/提交阶段故障注入和孤立文件清理验证。
- [官方 UI 本地保存状态与宿主不同] → 检查实际 embed 事件和状态呈现，以服务端确认状态为准，必要时最小配置或定制。
- [外部素材及字体不可达] → 核心资源本地提供，验证断网工作流，保留可选外网功能并注明依赖。
- [原生 SQLite 模块及编辑器构建依赖] → 容器固定兼容 Node LTS 构建环境，锁定依赖与 submodule，实际安装时验证目标服务器架构。

## Migration Plan

1. 建立 workspace、依赖 lockfile、数据库迁移和测试命令，首次迁移创建空 schema，不预置默认账号。
2. 构建产品和固定编辑器产物，Compose 启动并检查持久化路径可写，通过局域网初始化注册管理员。
3. 完成新建、导入、自动保存、跨窗口占用、停用、永久删除与容器重建验收。
4. 初次发布无旧业务数据迁移；后续升级执行显式 schema 迁移，禁止启动时清空数据。回退仅在旧代码兼容现有 schema 时使用旧镜像，否则停止并处理迁移，不承诺无备份的数据回滚。
