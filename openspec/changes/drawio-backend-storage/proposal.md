# Proposal

## Why

官方 draw.io 编辑能力已成熟，但当前产品仓库仅有目录骨架，缺少账号归属、服务器持久化和可靠的自动保存。需要为不超过 5 位熟人建立局域网绘图服务，在保留官方编辑器升级能力的同时，让文件管理与数据保存由产品统一负责。

## What Changes

- 增加一次性管理员注册、管理员创建普通账号、登录和密码管理、账号停用及基于归属的授权；管理员拥有所有文件的操作权限。
- 增加中文文件列表、新建、打开、重命名、文件名搜索、永久删除、原生 `.drawio` 导入及下载；不做文件夹，用户内文件名唯一。
- 使用 SQLite 管理元数据，文件系统保存完整原生文档，单文件默认限制 20 MiB，支持配置调整。
- 嵌入固定版本的自部署 draw.io，通过消息桥接实现约 2 秒防抖、持续修改约 10 秒触发的自动保存，以及服务端成功确认、错误提示和未保存退出保护。
- 增加按文件的服务端编辑租约和保存版本校验，跨浏览器及设备禁止并行编辑；锁每 10 秒续租，60 秒过期，不支持抢占或删除占用中的文件。
- 使用 Docker Compose 在单台服务器以同一 HTTP 入口部署，支持未来 HTTPS；核心编辑与存储不依赖外网，保留嵌入模式可用的官方在线素材和外部 URL 图片功能。
- 明确首期不做公开注册、云盘接入、协作编辑、历史版本、回收站、备份、跨关闭恢复草稿、账号删除、角色变更界面和移动端编辑验收。

## Capabilities

### New Capabilities

- `user-accounts`: 初始化管理员、会话、密码、账号管理与文件访问授权。
- `drawing-files`: 文件管理、命名与搜索、原生文档导入下载、容量限制和持久化。
- `editing-sessions`: 文件独占编辑、租约生命周期、版本冲突和占用时操作限制。
- `editor-integration`: 官方编辑器嵌入、自动保存调度、状态与失败反馈、未保存内容保护和官方功能兼容。
- `self-hosted-deployment`: 单机 Compose 部署、持久化、同入口访问、离线核心能力和支持范围。

### Modified Capabilities

无；项目当前没有既有规格。

## Impact

- 新增 `apps/web`、`apps/server` 的产品实现，以及 `packages/editor-bridge` 的协议与保存状态管理；按需建立 `packages/api-contract`。
- 新增账号、文件、租约等 API、SQLite 数据结构及文件持久化协议。
- 新增依赖管理、构建与验证命令，及 `deploy`、`scripts` 的容器与部署配置；技术栈方案见设计。
- `vendor/drawio` 继续以 submodule 固定 `v32.0.2`（`2201e54`），优先通过宿主与启动配置集成，仅在确认必要时最小定制 fork。
- HTTP 局域网部署不提供传输加密；无备份、版本与回收站意味着磁盘故障、覆盖和永久删除不具备产品级恢复能力。
